1. Experiment boundary

Training is unchanged: posterior(qpos, future actions, future force intervals)
produces a sampled 32-dimensional latent for the decoder. The conditional prior
continues to match detached posterior statistics using detached online features.
The fixed-normal posterior KL weight, prior-match weight, force losses, pooling,
network dimensions, optimizer, and data processing are unchanged.

The new option is --contact-latent-mode prior_mean. Validation feeds the conditional
prior mean, computed from current images/qpos and causal force history, to the
decoder. There is no future label input to this prediction path, and no prior
sampling. Model evaluation mode disables dropout.

At every validation event:
  held_out_validation: prior_mean metrics used for ALL early stopping and selection.
  zero_latent_reference: metrics from the same weights, episodes, and anchors with z=0.
The reference does not update counters or save a second set of best checkpoints.
This currently makes two evaluation passes; validation time increases, while the
number of optimizer updates per epoch and validation frequency stay unchanged.

For wrench6, best.pt / best_force.pt / best_moment.pt select action / force / moment.
For sensor_force3, there is no moment objective/checkpoint. Endpoint and interval
physical errors retain the existing 2/3 + 1/3 composite within each physical unit.

2. Preserved profiles and tensor shapes

The launcher supports wrench6 and sensor_force3 from the raw_v3 sensor data.
Choose the history profile explicitly to match the comparison experiment:
  10 ms: history [B,20,8,D], with roughly 3 native samples per interval.
  50 ms: history [B,4,20,D], with roughly 15 native samples per interval.
D is 6 or 3. Padding masks describe valid native samples.
Future endpoint [B,20,D], high-rate capacity [B,20,8,D], supervised nominal rate
300 Hz (3 slots per 10 ms), action [B,20,7], latent [B,32].
The history duration, action horizon, and future force horizon all remain 200 ms.
Mean/max/last pooling is unchanged. This change does not add prior reconstruction.

Both profiles inherit: split 40/10/5, seed 0, batch 8, episodic_uniform, 5 updates
per epoch, validation/checkpoint every 250 updates (50 epochs), max 20000 epochs,
warmup 3000 epochs, patience 20 validation events, relative improvement 0.001,
and the representation's existing optimization.json (including its loss weights).

4. Metadata, resume, inference and comparison

New Contact manifests/checkpoints contain run_config.contact_latent_config:
  version: real_robot_contact_latent_v1
  training: posterior_sample
  evaluation: zero or prior_mean
  deterministic_prior: true
  zero_reference: true only for prior_mean

Old checkpoints with no contact_latent_config mean zero, preserving compatibility.
Resume automatically inherits the saved mode and rejects switching zero/prior_mean
before restoring state. This prevents mixing early-stop histories and checkpoints.
The standard launcher pins prior_mean; use a separate directory for a new experiment.

evaluate_real_robot.py inherits the checkpoint mode by default. For a same-weight
comparison, explicit overrides are allowed and recorded in the report:

  python scripts/evaluate_real_robot.py --checkpoint /path/to/best.pt \
    --data-root /path/to/data --split-role validation --stride 10 --batch-size 8 \
    --contact-latent-mode prior_mean --output /path/to/new_prior_report.json
  python scripts/evaluate_real_robot.py --checkpoint /path/to/best.pt \
    --data-root /path/to/data --split-role validation --stride 10 --batch-size 8 \
    --contact-latent-mode zero --output /path/to/new_zero_report.json

The causal RealRobotPolicyAdapter.from_checkpoint also inherits the saved mode.
predict/predict_prepared accept explicit zero, prior, or prior_mean overrides;
prior and prior_mean both use deterministic prior means in this adapter.
Existing direct adapter construction defaults to zero.

Legacy hardware scripts under scripts/deployment/ explicitly pin z=0 and some
pin particular checkpoint hashes. They were not changed or run in this experiment.
Using a new checkpoint for actual robot control requires adapting that deployment
entry separately; the shared inference adapter and offline evaluator are ready.

5. Monitoring

  python scripts/monitor_real_robot_training.py --run-dir /path/to/run --watch

The monitor states posterior training / prior_mean selection and shows zero
reference action, endpoint-force, interval-force, and (for wrench6) moment errors.
Existing per-objective early-stop counters and best checkpoint displays are retained.

6. Implementation and checks

New contact_latent_mode.py provides the versioned mode contract, resolution,
validation, and resume identity checks. Existing evaluation functions propagate
the selected mode. The runner keeps reference metrics in a separate namespace.
The causal adapter loads the saved mode; model.forward_train and loss definitions
are untouched.
