Experiments (fresh initialization, seed 0)
-----------------------------------------
Existing completed 4090 contact-prior h10ms beta=10 run is the reference.
1. beta1: constant posterior KL coefficient 1.
2. warmup1000: linear 0 -> 10 during the first 1000 sampling epochs,
   then constant 10. 40 training episodes / batch 8 = 5 updates per epoch.
   For s completed optimizer updates, the NEXT update uses
       beta(s) = 10 * min(s / 5000, 1).
   Update 1: 0; update 2501: 5; update 5000: 9.998; update 5001+: 10.
   This schedules KL only, not learning rate. No extra schedule state advances
   on validation, saving, or resume. Resume uses checkpoint global_step.

Loss
----
L = L_action + L_endpoint + 0.5 L_interval + beta(s) KL(q || N(0,I))
    + KL(stopgrad(q) || p).
Only the coefficient of the posterior-to-standard-normal KL changes.
Prior matching keeps weight 1 and the original detach direction.
Training decoder uses posterior samples. Validation, stopping and all best
checkpoint selection use deterministic prior_mean. Zero-latent validation is
reference-only on the same model and frozen windows.

Unchanged experiment settings
-----------------------------
Raw v3 sensor observations/ee_wrench Fx/Fy/Fz/Tx/Ty/Tz (N, N*m).
History 20 x 10 ms; future force 20 x 10 ms; action 20 x 10 ms.
Pooling mean/max/last; latent dimension 32; architecture and prior ReLU unchanged.
Fixed 40/10/5 recording split; train-only normalization; fixed validation stride
10 (2505 windows on this dataset); episodic_uniform; batch 8; seed 0.
Main/backbone learning rate 1e-5; weight decay 1e-4; gradient clipping norm 1.
20000 sampling epoch ceiling; validation/checkpoint each 250 updates (50 epochs).
Multi-metric stopping: minimum 3000 epochs, patience 20, relative improvement .001.
Do not reset early stopping references or best records when KL warmup ends.
Best action, force and moment checkpoints can legitimately be selected during
warmup; beta at selection is recorded. Also inspect post-warmup trajectories.
best.pt, best_force.pt, best_moment.pt and last.pt remain separate.

Interfaces and compatibility
-----------------------------
real_robot/kl_schedule.py: immutable PosteriorKLSchedule, pure weight(s), resume
identity and legacy fallback. Missing schedule = saved constant posterior weight.
--posterior-kl-schedule constant|linear_warmup (Contact only)
--posterior-kl-warmup-epochs INTEGER (positive for linear, 0 for constant)
The optimization JSON posterior_kl_weight is the fixed value / warmup target.
Omitted schedule flags on resume inherit the checkpoint contract. Changed
schedule, target, warmup or steps-per-epoch are rejected before restoring state.
Omitting --optimization-config on resume also inherits the saved optimization
settings (including beta=1); an explicitly supplied different config is rejected.
The manifest and every checkpoint store the schedule; checkpoint additionally
stores completed updates and last/next coefficient. Old constant-10 behavior
and legacy checkpoints remain supported. Inference interfaces are unchanged.

Observability
-------------
Each Contact update records raw loss_posterior_kl, posterior_kl_beta,
loss_posterior_kl_weighted, loss_reconstruction, and posterior/prior mu RMS,
batch-centered mu RMS, sigma mean. These diagnostics reuse the training forward
(dropout active); they are NOT evaluation statistics and add no RNG draws.
Monitoring displays schedule, actual last beta, weighted KL, reconstruction and
latent diagnostics alongside prior_mean / zero validation and early-stop counts.
Do not rank models by total loss across different beta settings. Compare action,
force and moment physical validation errors, prior_mean-minus-zero predictions,
and latent variation. Nonzero mu alone does not establish decoder use of z.
